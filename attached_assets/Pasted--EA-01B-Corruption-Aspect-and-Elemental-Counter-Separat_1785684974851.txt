# EA-01B: Corruption Aspect and Elemental Counter Separation

## Objective

Complete the Elemental Counter overhaul using the current BM-2026-08-02 mechanics as the baseline.

The finished system must have only one elemental matchup calculation:

```text
Hero element versus enemy weakElement
```

It applies only to eligible hero Strike effects and grants ×1.30.

Enemy fantasy identity, clinical domain, clinical appropriateness, hero expertise, and Care Pathway advancement must remain independent from Elemental Counter.

Do not rebalance HP, Stability, AP costs, base skill values, resistances, or rewards during this migration.

---

## 1. Preserve Existing Working Features

Keep:

* `weakElement`;
* +30% Elemental Counter for eligible Strikes;
* Verdantha’s phase weakness overrides;
* Storm weakness for the Silent Infarct;
* River weakness for Fever Shade;
* Protection weakness for Ward Cascade;
* Forge and Filter phase weaknesses for Verdantha;
* per-target calculation for multi-target attacks, if already present.

Do not revert to `weakSystem`.

---

## 2. Replace Enemy Elemental Identity

The current enemy fields described as primary and secondary elemental `System` must no longer determine combat bonuses.

Add canonical fields:

```text
corruptionAspect
secondaryCorruptionAspects
weakElement
primaryAffinity
secondaryAffinities
```

### `corruptionAspect`

This is a fantasy description of what the corruption embodies.

Examples:

```text
depletion
suffocation
inferno
metabolic_lock
contagion
silent_ischemia
ward_collapse
rampant_overgrowth
toxic_accumulation
delirium
```

It is not one of the ten hero elements and does not provide a multiplier.

### `weakElement`

This remains one valid hero element or `null`.

Boss phases may override it.

### Clinical affinities

Continue using clinical affinity fields for domains such as:

```text
Fluid/Hydration
Airway/Respiratory
Fire/Inflammation
Protection/Immune
Energy/Metabolic
Storm/Cardiac
Mind/Neuro-Psych
Growth/Endocrine
Filter/Renal
Wound/Tissue
Community/Public Health
```

Do not derive affinities from `weakElement`.

---

## 3. Retire `systemMod`

Audit the implementation of `res.systemModifier` and every `systemMod` use.

The current reference describes it as a bonus when the hero or skill system matches the enemy’s primary elemental system. That old behavior must be removed.

### Strike

The final Strike formula must not contain an elemental system-match modifier in addition to Elemental Counter.

Elemental contribution must be only:

```text
elementalCounterMod =
  1.30 when eligible hero Strike and hero.element equals enemy.weakElement
  1.00 otherwise
```

### Stabilize

Stabilize must never receive an elemental or system-match bonus.

Remove elemental `systemMod` from Stabilize.

### Other actions

Elemental matching must not increase:

* Stabilize;
* Shield;
* Assess;
* Reassess;
* Protect;
* Escalate;
* Cleanse;
* Support;
* item effects;
* card effects;
* Clinical Cue effects;
* Care Pathway rewards.

### Migration safeguard

Before deleting `systemMod`, determine whether it contains any non-elemental clinical logic.

If it does:

1. separate the clinical logic;
2. migrate it into Intervention Fit or another explicitly named clinical evaluator;
3. remove the elemental comparison;
4. document what was preserved.

Do not silently delete unrelated clinical behavior.

## 5. Weakness Assignment Principles

A weak element represents the fantasy force that disrupts the corruption.

Examples:

* River replenishes Depletion and extinguishes Inferno.
* Air breaks Suffocation and airway confinement.
* Fire purifies a Contagion Seed.
* Energy restarts a Metabolic Lock.
* Storm interrupts rhythm-based or ischemic corruption.
* Mind clears fog, panic, and cognitive disorganization.
* Filter removes overload and restores internal balance.
* Forge cuts back or contains uncontrolled growth.
* Protection restores barriers and contains spread.
* Growth counters relapse, decay, and failed recovery.

The interface must not present these as real-world medical treatments.

## 6. Hero Skill and Action Audit

Audit every combat-capable action source:

* hero basic skills;
* upgraded skills;
* ultimates;
* passives that trigger actions;
* equipment-granted actions;
* items;
* cards;
* temporary actions;
* call actions;
* tutorial actions;
* event actions;
* companion or summon actions.

For each action, record:

```text
action ID
source hero or system
action type
whether it contains a Strike component
whether an acting hero exists
element used for Elemental Counter
clinical tags
clinical affinities
current system fields
current systemMod behavior
Elemental Counter eligibility
changes made
```

### Eligibility rule

Elemental Counter activates only when:

1. the effect is mechanically classified as Strike;
2. the effect has an acting hero;
3. the hero has a valid element;
4. the target has a current `weakElement`;
5. the values match.

### Multi-effect skills

A skill containing both Strike and Stabilize components must apply Elemental Counter only to the Strike component.

Do not multiply the entire combined skill.

### Items and cards

Items, cards, environmental actions, and system-generated effects default to ×1.00 because they do not have a hero element.

Only permit Elemental Counter when an action is explicitly executed through a hero and uses that hero’s element.

### Damage over time

When an eligible Strike applies damage over time, use the existing status architecture consistently.

Preferred behavior:

* determine Elemental Counter when the Strike lands;
* snapshot the resulting Strike potency;
* do not recalculate the matchup on every tick.

## 7. Clinical Separation

Elemental Counter must not determine:

* Intervention Fit;
* treatment correctness;
* clinical tags;
* Clinical Expertise;
* Care Pathway advancement;
* Clinical Cue correctness;
* affinity strength or weakness;
* whether an action is contraindicated.

A clinically bad Strike may trigger Elemental Counter but must still remain clinically bad.

Example:

```text
Bad Intervention Fit × Elemental Counter
0.00 × 1.30 = 0
```

Under the current BM-2026-08-02 treatment values, Elemental Counter cannot rescue a contraindicated treatment.

---

## 8. Care Pathway Compatibility Check

Search for Care Chain or Care Pathway logic that grants advancement when:

* action system matches enemy system;
* action element matches enemy weakness;
* skill system is Universal;
* hero element matches `weakElement`.

Remove elemental matching as a pathway relevance condition.

Pathway relevance must eventually depend on:

* required pathway role;
* Strong or Appropriate Intervention Fit;
* step-specific clinical tags where required.

Do not perform the full CC-01 pathway overhaul in this push. Only remove elemental dependency and preserve current pathway progress.

## 10. Legacy Compatibility

During migration, old content may still contain:

```text
system
secondarySystem
```

Normalize these fields when loading content, but do not pass them into the combat multiplier engine.

Use a schema version and compatibility adapter.

The runtime enemy model must use canonical fields only.

Development builds should warn:

```text
Deprecated enemy system field found on cardion_echo.
Converted to corruptionAspect; no combat modifier applied.
```

New or resaved data must not write legacy system fields.
