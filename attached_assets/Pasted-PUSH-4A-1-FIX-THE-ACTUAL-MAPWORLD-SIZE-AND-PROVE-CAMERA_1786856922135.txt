2. FIX AUTHORED-WORLD CALCULATION
==================================================

When worldTileSize is a valid positive number:

computeHexWorldCoords MUST NOT use the viewport-fit sizing algorithm.

It must build the world from the ACTUAL rendered extent of every authored tile.

Use the same axial formula already owned by hexWorldCoords:

rawLeft =
  q * Q_STEP * sz

rawTop =
  (r * R_STEP + q * Q_VOFF) * sz

For every authored tile calculate:

minLeft
minTop
maxRight  = rawLeft + sz
maxBottom = rawTop + sz

Then establish a world-space margin around the tile footprint.

Use approximately:

worldMargin = sz * 0.65

This margin is part of the painted MapWorld and provides room for:
- player sprite overflow
- encounter props
- jade glow
- map composition near edges

Then:

originX = worldMargin - minLeft
originY = worldMargin - minTop

worldWidth =
  ceil(maxRight - minLeft + worldMargin * 2)

worldHeight =
  ceil(maxBottom - minTop + worldMargin * 2)

axialToWorld(q,r) must return positions using that SAME origin:

left =
  q * Q_STEP * sz + originX

top =
  (r * R_STEP + q * Q_VOFF) * sz + originY

cx = left + sz / 2
cy = top  + sz / 2

Do NOT afterwards clamp worldWidth/worldHeight back to:

containerWidth
containerHeight

Do NOT scale sz downward to make the whole chapter visible.

The Chapter map is intentionally larger than the mobile viewport.
