PUSH 4A — PROVE AUTHORED WORLD SIZE AND RESTORE PLAYER-FOLLOW CAMERA

Do NOT change fog erasure behavior yet.

Current problems observed:

1. Camera is not visibly following the exploration sprite.
2. Fog/background diagnostics are showing approximately the same dimensions
   as the visible map area.
3. If MapWorld is not larger than the viewport, the camera clamp has nowhere
   to move.
4. Fog coverage cannot be evaluated until world geometry is correct.

==================================================
A. AUTHORITATIVE GEOMETRY
==================================================

Chapter map geometry must use authored-world sizing.

HexMapLayer already receives:

worldTileSize={AUTHORED_MAP_TILE_SZ}

Verify this value actually reaches:

computeHexWorldCoords(
  tiles,
  containerWidth,
  worldTileSize
)

Do not silently fall back to viewport-fit sizing.

For Chapter 1:

tile size must be AUTHORED_MAP_TILE_SZ.

The world must be calculated from the complete authored hex footprint,
not resized so the complete map fits the viewport.

==================================================
B. ADD A HARD DEV ASSERTION
==================================================

In Chapter 1 development mode:

if the world is effectively the same size as the viewport on both axes,
show a clear warning:

CAMERA WORLD FAIL
World is viewport-fit; authored map sizing is not active.

Do not assume exact expected pixel values because viewport sizes vary.

Instead verify:

worldWidth > viewportWidth
OR
worldHeight > viewportHeight

For Chapter 1 mobile layout we expect meaningful pan space.

Display:

Viewport: W × H
MapWorld: W × H
Background: W × H
FogOfWar: W × H

MaxCameraX
MaxCameraY

At least one camera max should be > 0 for Chapter 1.

==================================================
C. MAKE CAMERA RUN IDENTITY ROBUST
==================================================

Current camera movement detection effectively uses:

tiles.length
+
currentTile.id

That is not enough to uniquely identify a new map attempt.

Two different runs can:
- both have 30 tiles
- start on the same tile ID

and therefore look identical to the camera effect.

Add a camera run identity using the actual run seed.

Pass/use:

runSeed

Camera key concept:

cameraRunKey =
  runSeed
  + worldWidth
  + worldHeight
  + tileSize

Player key:

playerKey = currentTile.id

Camera reposition must occur when:

- runSeed changes
- currentTile changes
- worldWidth changes
- worldHeight changes
- viewport width changes
- viewport height changes

==================================================
D. CAMERA FOLLOW
==================================================

On every successful player-tile change:

calculate:

desiredX =
  viewportWidth / 2 - playerTileCenterX

desiredY =
  viewportHeight / 2 - playerTileCenterY

then clamp to the exact Chapter background bounds.

Camera behavior:

middle of map:
player stays near center

near edge:
camera reaches clamp
player continues toward screen edge

Do not force player centering beyond map bounds.

==================================================
E. CAMERA ANIMATION
==================================================

Keep the existing concept:

player sprite movement ≈ 220 ms
camera follow ≈ 230 ms

But ensure the camera animation is triggered from the same
currentTile change that triggers the player tween.

Cancel/stop an existing camera animation before beginning the next follow
so rapid movements do not leave an old camera animation running.

Manual pan still works.

After the next player movement, automatic follow resumes toward
the new player's position.

==================================================
F. RECENTER
==================================================

Recenter must compute/retain the CURRENT player's camera destination.

It must not point at:
- run start
- 0,0
- previous player tile
