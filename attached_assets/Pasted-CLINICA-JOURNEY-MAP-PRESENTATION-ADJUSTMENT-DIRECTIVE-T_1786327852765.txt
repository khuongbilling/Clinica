CLINICA JOURNEY MAP — PRESENTATION ADJUSTMENT DIRECTIVE

This is a targeted refinement of the existing Journey map.

Do NOT rewrite or replace:
- fixed chapter map templates
- encounter randomization
- shift system (Day / Evening / Night)
- boss key progression
- stamina movement
- battle triggering
- JourneyRun persistence
- bottom navigation
- chapter gating

Keep the existing gameplay systems.

This task is ONLY to improve the visual rendering and map readability.

NEW PRESENTATION RULES:

1. The chapter environment must be treated as ONE continuous painted map.
   - Do not render the map as many floor blocks stitched together.
   - Do not chop the environment into square or tile-sized background chunks.

2. Hexes are an interaction/grid layer placed over the environment.
   - Most hex interiors should be transparent.
   - The player should mostly see the painted environment underneath.
   - Hexes should read as movement cells, not as separate floor cards.

3. Fog-of-war must be visually continuous.
   - No blocky fog tiles.
   - No square fog chunks.
   - Fog should feel like one seamless atmospheric layer.

4. Baseline player field of vision:
   - reveal radius = 1 hex from current tile.
   - This includes the current tile and adjacent tiles.
   - Future skills/class bonuses may increase this to 2+.
   - Build this as a configurable value, not a hardcoded one-off.

5. Use three visibility states:
   - visibleNow
   - exploredButOutOfVision
   - unexplored

6. Encounter rendering should use 2.5D world pieces where appropriate.
   - Player sprite: 2.5D chibi/donghua style
   - Merchant: 2.5D cart / NPC encounter object
   - Treasure: 2.5D chest object, with actual treasure tier represented visually
   - Area Boss: 2.5D boss creature/object
   - Normal battle encounter: hidden enemy details, but represented by a 2.5D battle marker or encounter pedestal
   - Ward Events: later can use 2.5D NPC / prop / shrine / hazard representation

7. Do NOT use CSS/vector/SVG final substitutes for map pieces that should be illustrated assets.
   - No CSS-drawn hex buttons as final art
   - No fake chest icons drawn in code
   - No fake boss stand-ins drawn in code
   - Use raster asset-based rendering

8. Day / Evening / Night must preserve the same geometry.
   - Same map layout
   - Same gate location
   - Same start tile
   - Same hex grid
   - Only visuals / ambience / encounter distribution differ

9. Current dark map treatment should be interpreted as the NIGHT style.
   - Day should be brighter and clearer
   - Evening should be a true twilight transition
   - Night should retain the darker moody version

Implement this in small pushes only.
